# 随包版原生 Doris 复现说明

修订版的两个执行入口、新增独立参考程序和公开逐次证据可单独复现。[跨证券与窗口专项复现](lookup-window/复现说明.md)

本目录用随包的 Java 工件做测试。归档中的压缩 JSON 可以用 Python 标准库 gzip 和 json 直接读取。所有数据库计时均来自本机运行，归档的独立预期用于判分。

## 直接使用 GitHub 目录

在仓库根目录执行以下命令。只需 Python 3 标准库。脚本以 548 条工作台请求和 112 条直接 JDBC 重放记录为输入，对比名单摘要，计入失败、超时和截断，核算各组分母及 10 秒内返回数，并从 30 对计时样本重算两种基线的 P95 加速比。

```sh
cd reports/competition-review/2026-11-29
python3 工具/check_public.py
```

逐例文件的 expectedDigest 和 actualDigest 是返回行数组经 UTF-8 紧凑 JSON 编码后的 SHA-256。无序黄金用例在编码前排序，保留重复项。sourceSha256 用于与原始证据包内对应文件交叉核对。公开摘要可复核本报告的统计；完整名单的逐行对照需使用原始证据包。 [逐例判定](逐例判定.jsonl) · [原始证据路径及哈希](证据索引.md)

## 使用原始证据包离线复核

解压原始证据包，在解压所得的 `原生Doris验收` 目录运行以下命令。第一条校验归档文件的字节。第二条从每次响应重新比较返回列、完整名单、顺序和截断标志，并重新计算分位数。审计脚本会核对各组用例数量及每次计时样本数量。

```sh
shasum -a 256 -c SHA256SUMS
python3 工具/audit.py .
```

主报告使用最近秩分位数，即将完整样本从小到大排序，取序号为 ceil(样本数 × 分位) 的值。接口每个请求的时钟从发送开始，到客户端读完响应体为止。响应内同时保存编译、排队、主 SQL、取数及服务端总耗时。HTTP 总耗时还覆盖快照检查、缺失数据统计、计划分析及响应传输。主 SQL 单独复测使用同一个 JAR 的 PROJECT_REFERENCE 模式、JDBC 绑定和完整读取，关闭 SQL 和查询结果缓存，单个语句超时上限 60 秒，达标判断仍使用 10 秒。

## 在本机重跑

工作区中保留 dsl-doris-compiler、csv、本机Doris测试环境和本验收目录。项目 Python 为 dsl-doris-compiler/.tools/judge-venv/bin/python。JDK、MySQL 只读账号、本地访问令牌、数据清单与来源证书沿用已准备的本机环境。证据包保留数据清单和导入回执，原始 CSV 单独按哈希取得。数据库账户密码和令牌由本机配置目录提供。

从工作区运行下列命令。在未使用的端口 8082 启动同一 JAR 的独立实例，服务端返回上限 10,000 行。对照阶段 8081 的原始配置上限为 1,000 行。两端口的控制执行均使用 10 秒语句超时、1 亿估算扫描行和 2 GiB 单查询内存限制。

```sh
bash 原生Doris验收/工具/start.sh
```

另开终端，在工作区的新输出目录中运行。用例顺序的随机种子在脚本内固定。重跑时保留原始归档，使用新建目录。

```sh
p=dsl-doris-compiler/.tools/judge-venv/bin/python
t=原生Doris验收/工具
out=$(mktemp -d "$PWD/复测.XXXXXX")
"$p" "$t/native.py" "$out/接口全量" complex expanded fields golden
"$p" "$t/native.py" "$out/接口补充" holdout
"$p" "$t/native.py" "$out/冻结组合与排名" combination rank
"$p" "$t/diagnostics.py" "$out"
"$p" "$t/load_http.py" "$out/接口并发"
```

如从附件开始搭建，将原项目解压为 dsl-doris-compiler。随新证据包提供的“输入补充”保留了原附件未包含的两个字段矩阵文件，应按其中相对路径放回项目。prepare.py 及 history_oracle.py 使用原始 CSV 校验后生成的只读 DuckDB。数据库在另一台机器上重建时，须使用重建所得的 build 报告记录实际路径和文件哈希。准备脚本会重新核对该哈希。

## 复算预期和长周期性能

以下命令均在工作区执行。附件路径应指向用户提供的原 ZIP。verify.py 会重新读取原始 CSV、生成配置扩展，并保存独立的 306 行预期。prepare.py 检查附件与受测 JAR，执行真实的正式门禁，复算 48 条复杂用例并生成补充集。frozen_matrices.py 使用原始表和独立 Python 公式生成组合及排名预期。仅复查测试结论时可以直接使用本次归档中的预期。

```sh
attachment='/原始附件的路径/行情选股DSL编译系统-参赛报告与测试证据-20261128(1).zip'
"$p" dsl-doris-compiler/reports/competition-review/2026-11-28/verify.py --data-root csv --output "$out/配置扩展"
"$p" "$t/prepare.py" "$out" "$attachment"
"$p" "$t/frozen_matrices.py" "$out"
"$p" "$t/history_oracle.py" "$out"
export JUDGE_ORACLES="$out"
mkdir "$out/特征复测"
"$p" "$t/sharded_build.py" "$out/特征复测" history
"$p" "$t/performance.py" "$out/特征复测" history --rounds 30
"$p" "$t/performance.py" "$out/特征复测" aggregate --rounds 30
"$p" "$t/performance.py" "$out/特征复测" no-page-cache --rounds 20
"$p" "$t/performance.py" "$out/特征复测" matrix --rounds 5
```

历史特征在新的诊断库构建，按每只证券的完整历史分片校验 9 个当前值与极值字段。每个分片都做全外连接，验证行缺失、多余行和值差异。滚动特征原项目的增量构建失败记录保存在 build-rolling。单独的全量构建脚本使用完整观察窗口逐值复核。每次有效计时都使用相同 JAR、相同输入、相同只读连接、相同返回顺序，两条路径交替先后执行。文件内的 buildSecondsIncludingWslTransport 为原脚本保留的字段名，本次实际传输为本机 Docker。

每个日期 / 市场组合共享规则模板，各矩阵之间也可能出现相同 DSL。接口表格按预定矩阵分别汇总。冻结黄金集属于项目内部。可用性判定保留超时、资源拒绝、后端错误、名单不匹配和超时限响应。真实主 SQL、带诊断的工作台请求和特征加速的 JDBC 读分别报告。

## 查阅资源限制和睡眠影响

2026 年 11 月 28 日深夜的两个批次与 Mac 合盖睡眠重叠。带“合盖时段”的目录保留第一次尝试，报告采用清醒时段独立重跑的结果。历史窗口基线与后续清醒补测分别保存在 history-30 和 history-recheck-30。工作台默认会在 2,000 ms 后结束仍未取得执行槽位的请求。遇到 TIMEOUT 时请查原件中的 message 字段，区分执行队列等待超时和 Doris 语句超时。

对诊断失败的主 SQL 可单独运行以下两项。第一项只重放本次 112 条中未成功匹配的用例，启用 Doris 溢写、将流水线任务并行度设为 1，并保留 60 秒超时和 2 GiB 内存限额。第二项重测最容易受到合盖干扰的一条长周期窗口基线，并增加同日期非空的新低用例。两项均使用同一个 JAR。

```sh
"$p" "$t/diagnostics.py" "$out" --spill-retry
"$p" "$t/performance.py" "$out/特征复测" history-recheck --rounds 30
```

需要核对逐字段附加诊断，或重新计算按年份与市场的源数据聚合时，可以分别执行 quality.py、source_check.py。两种源上分别计算行数、每列非空数和整型值的精确和。保存的查询和结果支持离线复查。

```sh
"$p" "$t/quality.py" "$out"
"$p" "$t/source_check.py" "$out" raw
"$p" "$t/source_check.py" "$out" doris
```
