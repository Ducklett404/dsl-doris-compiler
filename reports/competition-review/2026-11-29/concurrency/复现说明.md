# 单节点工作台并发复测

## 离线复核

从仓库根目录运行。核验程序只依赖 Python 标准库。它检查每组 30 次请求的身份与顺序、客户端时钟区间、实际并发峰值、列名、行数、有序股票名单摘要、截断、数据质量摘要、快照指纹以及耗时和资源限额。失败响应保留在分母。基线包含真实的超时，因此只在修订版上启用全部请求的 10 秒门槛。

```sh
d=reports/competition-review/2026-11-29/concurrency
python3 "$d/check.py" "$d/baseline"
python3 "$d/check.py" "$d/accepted" --require-sla
python3 "$d/check_regression.py"
```

吞吐用正确完整响应数除以该批从首个请求发出到最后一个响应读完的实际墙钟时长。每次请求的延迟从发送到完整读取响应体。P95 采用最近秩。每个请求保留起止时间相对于本批开始的纳秒值，磁盘压缩和摘要计算在整批计时结束后执行。

## 真实 Doris 回放

使用相同的三表行情快照、只读账号和项目来源证书。Doris 4.1.3 容器限额为 4 核、7 GiB。构建需要 JDK 21 或以上和 Maven。可在第一阶段优化报告中核对数据来源与导入过程。[数据与工作台准备](../lookup-window/复现说明.md)

在仓库根目录构建并启动独立实例。以下命令使用修订版工作台的默认 4 个会话和 4,000 ms 等待时限。凭据使用当前环境的变量注入，证书由 `PROJECT_VALIDATION` 指向。复测上一版时使用基线受测 JAR 或在独立目录构建对应修订，使用该版本默认的 1 个会话与 2,000 ms 等待时限。[版本、哈希和运行参数](environment.json)

```sh
./mvnw -B package
./mvnw -B -f executor-doris/pom.xml test
export DORIS_DIAGNOSTIC_USER=dsl_project_reader
java -jar target/dsl-doris-compiler.jar serve-doris --bind-host 127.0.0.1 --http-port 8082 \
  --host 127.0.0.1 --port 19030 --user "$DORIS_DIAGNOSTIC_USER" \
  --password-env DORIS_DIAGNOSTIC_PASSWORD --project-validation "$PROJECT_VALIDATION" \
  --max-scan-rows 100000000 --max-return-rows 10000 --max-exec-memory-bytes 2147483648
```

另开终端，设置匹配服务端的 `DSL_HTTP_TOKEN`。输出需为新目录。每一轮两组负载都分别执行 1、4、8 并发。第一组沿用原有 6 条模板各 5 次，第二组使用固定的 30 条不同 DSL。首轮随机种子为 87，后续每轮加 1。旧版本的本次回放只跑 4、8 两档各一轮。始终串行运行各批，避免不同批次争用同一数据库。

```sh
d=reports/competition-review/2026-11-29/concurrency
out=$(mktemp -d)
python3 "$d/bench.py" "$out/accepted" --rounds 3
python3 "$d/check.py" "$out/accepted" --raw --require-sla
# 在切换到基线服务后
python3 "$d/bench.py" "$out/baseline" --workers 4 8
python3 "$d/check.py" "$out/baseline" --raw
```

在修订版服务上另跑同一组 112 条复杂 DSL 和 8 条跨证券边界。JDBC 独立准备、绑定并完整取数，关闭 SQL 及查询结果缓存。HTTP 使用相同的 10,000 行返回上限和冻结预期。原始响应和 SQL 以 gzip 保存，公开附件保留判定所需的逐次数据。

```sh
prev=reports/competition-review/2026-11-29/lookup-window
export DORIS_DIAGNOSTIC_URL='jdbc:mysql://127.0.0.1:19030/newzl?useSSL=false&allowPublicKeyRetrieval=true&socketTimeout=70000'
# 两个终端使用同一只读账号、DORIS_DIAGNOSTIC_PASSWORD 和 DSL_HTTP_TOKEN
python3 "$prev/replay.py" "$out/regression" --rounds 1
python3 "$prev/replay.py" "$out/edges" --rounds 1 --cases "$prev/edge-cases.json"
python3 "$d/check_regression.py" --raw "$out"
```

停牌和 NULL 边界可用安装了 DuckDB 的 Python 在内存中独立运行。用例对照手工写定的名单和诊断，以及编译器生成的全扫描参考路径。

```sh
python3 scripts/doris/test_project_recent_history.py
```
