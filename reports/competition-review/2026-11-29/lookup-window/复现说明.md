## 离线检查已发布的样本

从仓库根目录执行以下命令。检查器只用 Python 标准库，逐条检查原有预期摘要、完整名单的有序摘要、列名、截断、重复或缺失请求，并从逐次耗时重算分位数。任一串行请求超出 10 秒或结果不完整都会使检查失败。并发诊断在报告中单列。

```sh
d=reports/competition-review/2026-11-29/lookup-window
python3 "$d/check.py"
```

`cases.json` 保存全部 112 条 DSL、预期行数和预期摘要。原轮冻结的证券名单来自原始 CSV 的独立参考计算。两版使用相同的 112 条输入，其中 21 条属于本次修复的三类模板。摘要对按原顺序排列的二维字符串数组做紧凑 UTF-8 JSON 编码，然后取 SHA-256。相同股票以不同顺序返回会得到不同摘要。[随包版的独立预期与判定](../逐例判定.jsonl)

`edge-cases.json` 增加 8 条输入。其预期可在已由三份官方 CSV 构建的只读 DuckDB 上重新生成。参考程序直接读取原始列、按证券的实际交易记录计算均线与次数，并逐日读取目标证券的原始行情。证券停牌时以实际观察数构成窗口。目标当日缺失、窗口不足及扩展表哨兵值分别处理。原始库需要存在 `newzl.hsj_stock_hq_basic`、`newzl.hsj_stock_hq_ext` 和 `newzl.hsj_stock_code_info`。

## 构建并启动受控工作台

使用 JDK 21 或以上、Maven、Python 3 和已导入官方行情的 Doris 环境。重新生成边界预期时，Python 环境还需要 DuckDB。库、快照、视图、校验凭证和只读账号按原验收环境准备。[原验收环境与数据复现](../复现说明.md)

```sh
./mvnw -B package
./mvnw -B -f executor-doris/pom.xml test
export DORIS_DIAGNOSTIC_USER=dsl_project_reader
export DORIS_DIAGNOSTIC_URL='jdbc:mysql://127.0.0.1:19030/newzl?useSSL=false&allowPublicKeyRetrieval=true&socketTimeout=70000'
# 通过环境注入 DORIS_DIAGNOSTIC_PASSWORD、DSL_HTTP_TOKEN 和 PROJECT_VALIDATION（来源证书路径）
java -jar target/dsl-doris-compiler.jar serve-doris \
  --bind-host 127.0.0.1 --http-port 8082 --host 127.0.0.1 --port 19030 \
  --user "$DORIS_DIAGNOSTIC_USER" --password-env DORIS_DIAGNOSTIC_PASSWORD \
  --project-validation "$PROJECT_VALIDATION" --max-return-rows 10000 \
  --max-scan-rows 100000000 --max-exec-memory-bytes 2147483648
```

## 重跑并核对

在另一终端进入同一仓库，设置相同的 `DORIS_DIAGNOSTIC_URL`、`DORIS_DIAGNOSTIC_USER`、`DORIS_DIAGNOSTIC_PASSWORD` 和 `DSL_HTTP_TOKEN`。使用空输出目录以保留每次尝试。先测新增边界，再测全矩阵和专项重复，最后独立运行并发诊断。各阶段串行执行，避免争抢单节点资源。

```sh
d=reports/competition-review/2026-11-29/lookup-window
out=$(mktemp -d)
python3 "$d/replay.py" "$out/edges" --cases "$d/edge-cases.json"
python3 "$d/replay.py" "$out/final"
python3 "$d/load_probe.py" "$out/load"
python3 "$d/check.py" --samples "$out/final/samples.jsonl" \
  --edges "$out/edges/samples.jsonl" --load "$out/load/samples.jsonl" --raw "$out"
```

两条执行路径均使用完整取数。HTTP 计时始于发送 `/execute`，止于读完响应字节，涵盖排队、快照校验、计划估算、主 SQL、数据质量诊断和传输。JDBC 使用 `PROJECT_REFERENCE`，计时覆盖语句准备、参数绑定、执行、读取全部行和关闭结果集，单独关闭 SQL 与查询结果缓存。60 秒诊断超时用于保留慢查询的真实耗时，10 秒判定线相同。每轮以固定种子置乱，请求逐个发送。第二轮调换两个入口的先后次序。P95 取按耗时升序排列的第 ceil(0.95 × N) 个样本。运行目录保存完整 SQL、绑定参数、返回行、响应或失败信息，公开 JSONL 保留逐次耗时与结果摘要。

并发诊断复用随包版的 6 条 DSL，每个并发级别有相同的 30 次请求，固定随机种子为 87。原服务执行槽和 2 秒队列等待上限同样生效，失败请求计入分母。[原并发样本](../接口并发)
