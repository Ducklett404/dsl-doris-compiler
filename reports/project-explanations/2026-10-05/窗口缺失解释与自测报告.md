本轮状态：`PROJECT_WINDOW_EXPLANATIONS_PASS_FORMAL_BLOCKED`。项目内部解释与计算验证通过，官方完整快照及外部验收仍未通过；正式门禁未解除。

## 已完成的改进

1. 为输入增加 `inputId/window/role/requiredObservations`。同一指标的不同周期可区分；标识忽略源码位置、SQL 别名和 LIMIT。次数输入保留条件与阈值，相同值输入的重复调用可共用标识；原样本标记仍按数组位置对应。
2. 增加 `dataQuality.sampleDetails` 及 Markdown 日期解释。区分观察不足、来源 NULL、哨兵、衍生缺行、平坦区间、RSI 下跌均值为零与其他零分母。次数结果与历史条件未知分开披露，NULL 条件仍不计为命中。
3. 只为最多 20 个缺失样本增加一次有界只读历史查询，按实际观察行保留历史，再按市场/代码/日期三键关联衍生行情。没有缺失样本时跳过。相关日期上限 20、每只历史上限 10001 加 1 条探测行、字段上限 32、每个输入解释上限 250000 步。超限、跨证券查找或解释失败标为 `PARTIAL_DETAIL`，保留 SQL 缺失统计及主结果。
4. 补齐成交量/资金 position、资金次数与 close_together 的独立核对；接入本地统一自测与 CI 配置。CI 配置已本地解析，未触发远程 CI。

历史不足仅报告需要和观察到的记录数，不推测缺少哪些交易日。`relatedDates` 表示真实相关日期：NULL/哨兵/缺行日期与平坦或零分母的证据日期含义不同，不能统一称为缺失日期。样本解释不代表全部受影响证券的原因分布。

## 检查中修复的缺陷

历史 `position` 的旧 CASE 在当前值为 NULL、历史 MIN/MAX 非平坦时落入 ELSE，错误返回“中”。现在先判断当前指标是否 NULL，返回 NULL；较早 NULL 仍按已有历史 MIN/MAX 规则忽略。有限窗口完整性、边界等号、排序及次数规则保持原有定义。

新增 Java 回归及真实 Doris 合成场景验证：同一证券较早价格为 1、2，评价日为空时，不进入“中”的结果列表；解释明确列出评价日 SOURCE_NULL。证据：[真实场景](synthetic-final/historical-position-current-null.json)。
