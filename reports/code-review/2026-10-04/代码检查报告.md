## P1 问题

### R01：`/execute` 没有请求身份和权限检查

位置：`src/main/java/com/acme/dorisdsl/server/CompileHttpServer.java:43`；CLI 接入在 `cli/Main.java:297`。

`/compile` 在处理请求前调用 `RequestAuthenticator` 和 `PermissionGate`，`/execute` 却直接反序列化 JSON 并调用执行端点，没有认证、执行权限校验或可信身份传递。只读数据库账号和查询配额不能替代应用调用方授权。服务绑定外部地址或经代理暴露时，能访问端点的调用方即可使用服务数据库账号触发查询。

证据：`HttpServerTest` 的执行端点用例没有提供任何 Authorization 头，预期仍能进入执行回调。已有构造器也没有同时注入执行端点、认证器和权限服务的公开入口。

建议：统一两个入口的认证层，为执行定义单独的权限（例如 `EXECUTE_DSL`），可信身份从服务端产生；认证和授权必须在解析大请求体、编译及查询前完成。保留默认拒绝策略，并增加匿名请求不会触发执行回调的测试。

### R02：60 日均线优化缺少特征表日期覆盖门禁

位置：`stockslot/StockSlotAdvancedSqlCompiler.java:252`；`data/doris/ddl/005_performance_features.sql:33`。

选择特征表只判断窗口为 60、日期回看为 0、没有计数槽位，没有判断评价日期是否被特征表覆盖。DDL 只物化 `2026-04-14`，因此任何其他明确日期的 60 日均线仍会访问这张表。README 声称其他日期安全回退，与实现不一致。

复现输入：

```text
indicator('', '', '60日均线', '2026-04-13', '', '', '') > 1
```

优化 SQL 扫描 `newzl.stock_daily_features_v1` 并绑定 `2026-04-13`；参考 SQL 扫描历史行情。合成数据完整时，优化结果为空，参考结果为证券 A。

建议：把特征覆盖日期、快照、复权口径和刷新版本纳入注册表/规划门禁，匹配时才能走特征表；不匹配必须回退。至少补充验收日前一交易日和未覆盖日期的等价性测试。

### R03：特征表与明细路径的均线 NULL 策略不同

位置：`data/doris/ddl/005_performance_features.sql:19`；`stockslot/StockSlotAdvancedSqlCompiler.java:480`。

特征表先用 `WHERE closePrice IS NOT NULL` 删除记录，再计算 60 行窗口。明细路径保留这些记录，要求最近 60 行中非空计数为 60。存在一条收盘价为空的实际记录时，两条路径的回看范围和结果不同。文档要求不插值、完整窗口中有空值就返回 NULL；“停牌时根本没有记录”与“已有记录的指标为空”需要区分。

合成数据：证券 A 有 61 条记录，非空价格均为 2，最近 60 行内一条价格为 NULL，评价日为 `2026-04-14`。优化路径返回 A，`FULL_SCAN_REFERENCE` 不返回 A。两份生成 SQL 均直接来自本次打包的编译器。

建议：统一观测记录和停牌的定义，特征构建与明细计算复用同一个窗口契约；补充空值出现在窗口内部、新股不足窗口及不存在停牌记录的差分样例。修复后重新生成特征表及其数据版本。

### R04：复合 `BETWEEN` 表达式生成的占位符和绑定值不匹配

位置：`stockslot/StockSlotSqlCompiler.java:318`；`stockslot/StockSlotAdvancedSqlCompiler.java:468`。

渲染左值一次后，把含 `?` 的 SQL 字符串重复用于上下界，左值中的绑定值却只加入一次；绑定顺序也未随两次左值出现重新安排。

复现输入：

```text
(indicator('', '', '收盘价', '2026-04-14', '', '', '') + 1) between '[2,4]'
```

实际 SQL：`((m1 + ?) >= ? AND (m1 + ?) <= ?)`，加上日期共 5 个占位符；实际 bindings 为 `[2026-04-14, 1, 2, 4]`，只有 4 项。换成 5 日均线的高级路径也复现：6 个占位符、5 项绑定。进入 JDBC 后正常表达式不能执行。

建议：每次输出表达式都按 SQL 顺序生成绑定值，或先把复合左值投影为别名再复用。为 SQL 与 bindings 建立统一渲染结构，覆盖字面量、算术、范围两端和嵌套组合。

### R05：`screen-v1` 的 `IS NULL` 节点没有完整收集依赖

位置：`sql/DorisSqlGenerator.java:100`、`:370`。

通用收集函数和前缀指标收集函数均漏掉 `Ast.IsNull`，而最终 SQL 渲染函数支持它，导致依赖在 SQL 输出前没有建立。

两个实际复现：

```text
SCREEN ON 2026-08-07 WHERE CLOSE IS NULL LIMIT 5
SCREEN ON 2026-08-07 WHERE MA(CLOSE, 5) IS NOT NULL LIMIT 5
```

第一条编译成功，但 base CTE 只有 `symbol` 和 `trade_date`，最后引用不存在的 `close` 列。第二条抛出 `IllegalStateException: PREFIX_DAILY selected without prefix metrics`。

建议：统一 AST 遍历器，所有支持的节点必须递归收集其子节点；对字段、财务函数和窗口函数的 `IS NULL/IS NOT NULL` 补充端到端 SQL 验证。

### R06：某些非空 `CONS/EXIST` 槽位被接受后静默忽略

位置：`stockslot/StockSlotAdvancedSqlCompiler.java:393`、`:417`。

计数收集只识别比较运算的直接左右函数调用。调用嵌在算术表达式内，或布尔函数直接作为筛选条件时，槽位虽然通过校验，却没有创建计数窗口。

复现输入：

```text
indicator('', '', '收盘价', '2026-04-14', '', '', 'CONS>=3日') + 1 > 2
cross_above('', '', '收盘价', '开盘价', '2026-04-14', '', 'CONS>=3日')
```

两条均编译成功，SQL 不包含 `predicates` / `counted` CTE 或连续次数窗口；第一条变成普通当日价格判断，第二条只判断一次交叉。对照直接 `indicator(...,'CONS>=3日') > 1` 则有计数窗口。

建议：为每个非空计数槽位记录并确认其最终 lowering。实现明确的复合条件计数语义；暂不支持的形状必须返回稳定错误，不能把用户要求丢弃。

### R07：行业缺失被当成一个有效的共同分组

位置：`stockslot/StockSlotAdvancedSqlCompiler.java:381`。

`belong_industry` / `industry_max` 直接使用 `PARTITION BY hyBlkRefName,bizdate`，没有在行业为 NULL 时返回 NULL 的保护。LEFT JOIN 失败或行业缺失时，所有 NULL 行业证券被聚合为同一组，可能返回近似全市场均值/最大值并进入选股结果，违反函数文档的 `NULL_IF_INDUSTRY_MISSING` 契约。

首期冻结文件还明确标注：固定快照的 5686 条代码记录全部没有行业值，行业能力被排除。因此该边界在当前快照上很关键，不能仅作为罕见脏数据处理。

复现：缺失代码/行业数据的合成证券 A，收盘价为 2；`belong_industry('', '', '收盘价', '2026-04-14', '') > 1` 实际返回 A，正确的缺失行业结果应为 NULL，或者在首期范围门禁处拒绝执行。

建议：在编译/执行阶段落实快照能力范围；可用行业函数也应明确保护 NULL 行业，不能将缺失值作为正常分区。

## P2 问题

### R08：CLI 和 Docker 的 `/compile` 没有可用鉴权配置入口

位置：`cli/Main.java:415`、`:297`；`server/CompileHttpServer.java:21`、`:25`。

`serve`、`serve-doris` 均调用默认 `REJECT_ALL` 构造器。CLI 没有配置认证器的选项，Docker ENTRYPOINT 也调用 `serve`。因此 README 的正常 `/compile` 示例、Docker 和一键启动出来的编译接口都会拒绝请求，不能通过添加普通请求头修复。

建议：增加真实的服务端认证配置并注入 CLI，或提供受限制且明确命名的本机开发接入方式。不要简单改成默认放行；用 CLI/容器黑盒测试验证有凭据成功、无凭据拒绝。当前 HTTP 单测注入的是测试认证器，无法覆盖正式 CLI 配置缺失。

### R09：Windows 换行转换让冻结验收在干净仓库中失败

位置：`scripts/ci/verify-phase1-scope.ps1:49`、`:54`、`:68`。

本地 `core.autocrlf=true`，工作区在检查前完全干净。脚本对检出文件原始字节计算哈希，而冻结值以 LF 文件生成。

实测注册表哈希：

```text
工作区 CRLF：88f10bd1be20ff4881e1433bc6fadec9d9b80ab18f90fc89f22000644099bb1c
标准化 LF：  7431104d7fefd5561f682838384fd567c841fb09d8e29944f11e9be6080bd4cc
冻结期望：  7431104d7fefd5561f682838384fd567c841fb09d8e29944f11e9be6080bd4cc
```

这不是业务配置被改动，但 `test-all.ps1` 的第一步会直接停止。建议用 `.gitattributes` 固定被签名文本为 LF，并定义一致的哈希生成/验证口径；或在版本化契约中明确规范化规则。不要为适配某台机器而随意更新冻结哈希。

### R10：文法允许的 NULL 输入导致未受控 NPE

位置：`stockslot/StockSlotSqlArtifact.java:17`。

输入 `indicator('', '', '收盘价', '2026-04-14', '', '', '') = null` 被解析、通过语义检查并加入空绑定值，随后 `List.copyOf(bindings)` 因元素为 null 抛出 `NullPointerException`。HTTP 执行入口会归类为 500，而不是结构化语义诊断。

建议：先冻结 NULL 比较语义，再实现明确的 NULL 判断或拒绝不支持的用法；确实允许 SQL NULL 绑定时应使用允许 null 的不可变列表实现。为语法接受的 NULL 节点补齐错误契约。

### R11：正式 DSL 的比较运算未验证操作数类型

位置：`stockslot/StockSlotSemanticAnalyzer.java:136`。

分析器验证布尔连接和四则运算，却对普通比较直接返回 BOOLEAN，没有校验左右类型是否可比较。

实际复现：`indicator('', '', '收盘价', '2026-04-14', '', '', '') > 'abc'` 编译成功，SQL 绑定字符串 `abc` 和数值价格比较。数据库的隐式转换或拒绝会决定结果，违背强类型编译的目标。布尔值和数字等不兼容比较有同类风险。

建议：定义比较兼容性矩阵，特别区分 NUMBER/PERCENT、STRING、BOOLEAN、NULL 和 UNKNOWN；对有序比较、约等于、区间分别检查。未知类型应在进入执行子集前被解析为确定类型或拒绝。

### R12：HTTP 请求体和并发接入没有应用层上限

位置：`server/CompileHttpServer.java:40`、`:50`、`:98`。

Jackson 在检查 DSL 长度之前直接读取整个请求体，额外 JSON 字段可占用大量内存；虚拟线程执行器也没有请求级并发或排队配额。数据库单连接锁只限制执行阶段，不能限制同时进入 JSON 解析和编译的请求数量。启用外部绑定后，已有 DSL 的 100000 字符限制不能覆盖这些资源风险。

建议：为流式读取设置总字节数上限（超限 413），限制 JSON 结构/不必要字段，设置编译和执行的接入并发及有界等待，并在授权前拒绝大请求。无效 JSON 和字段类型应返回 400/422，服务端内部错误详情应避免直接返回客户端。本项为静态确认，未进行负载攻击或压力测试。

## 进一步完善建议

1. **从 SQL 字符串快照扩展到结果差分。** 每个优化路径均覆盖完整数据、窗口不足、内部 NULL、重复/缺失日期、未覆盖日期及市场/行业缺失。数据库验证使用隔离小数据，不依赖昂贵的 19 年基准才能发现基本语义问题。
2. **统一 AST 遍历与 SQL/绑定渲染。** `IsNull` 漏处理、复用含参数片段、计数槽位识别不全都与多处手写递归有关。共享访问器与结构化渲染结果可以减少同类缺陷；注册模板重复/重排参数也应加入测试。
3. **明确最小选取数量的运行契约。** `limit 5,10` 的 minimum 目前只记录在 `CardinalityConstraint` 计划节点，执行器没有校验实际结果是否至少 5 条。先确定不足时应返回空结果、诊断还是数量约束失败，再实现并测试；它不应被解释为分页 offset。
4. **为固定长度历史窗口减少扫描。** 高级路径普遍扫描 `bizdate <= 评价日` 的全历史；短窗口也会遍历 19 年数据。确定最大所需观测记录数后做正确的证券级回看裁剪，保留停牌、新股和嵌套窗口语义；无界“历史”与固定窗口分开规划。
5. **强化执行配额证据。** `parseEstimatedRows()` 当前取所有计划节点中最大值，不等于多个扫描节点总工作量；明确 EXPLAIN 门禁是估计，并验证服务器 Workload Group 的实际取消规则和账号绑定。快照登记的存在也应与所查询物理数据版本关联。
6. **整理测试和交付说明。** 主入口 `test-all.ps1` 没有聚合独立执行器/Python 测试；执行器已有单独 CI，不能再沿用旧 BUG 清单中“完全没有纳管”的结论。`SELF_TEST_REPORT.md` 仍记录 7 项测试的旧版本，应在发布索引中明确其历史用途，避免与当前验证混淆。
